# 助教课前检查清单

## 1. 开课前必须确认

- [ ] 课程仓库已发布，学生可匿名或凭课程账号访问。
- [ ] `lab-repo` 中有且只有假数据；真实密钥不在仓库中。
- [ ] 每台学生机都能同时满足 Node.js 24.9+ 和 Python 3.10+。
- [ ] 全局命令 `pi --version` 返回 `1.6.0` 或已记录的新兼容版本。
- [ ] 全局命令 `dsh --version` 返回 `0.2.2-rc.5` 或已记录的新兼容版本。
- [ ] [ChatECNU](https://chat.ecnu.edu.cn/) 的 Key 发放说明已发给学生。
- [ ] 已验证 Base URL `https://chat.ecnu.edu.cn/open/api/v1` 和 `ecnu-plus`。
- [ ] 用一个新账号或新配置目录，在 Pi 与 DSH 中各完成一次真实请求。
- [ ] 运行 `pwsh -NoProfile -File .\scripts\check-deliverables.ps1`。
- [ ] 按学生文档从干净目录走完 A1-A5、B1-B4；若 Key 不可用，暂停开课并
  向课程负责人报障，不能要求学生“自己猜端点”。
- [ ] 在共享屏幕中隐藏 Key，并提醒学生不要截图或提交凭据。

## 2. 推荐的干净机预验收

Windows PowerShell：

```powershell
node --version

dsh --version

```

预期 Python 测试全部通过；`pi` 与 `dsh` 的版本不低于 README 中的基线。

## 3. Pi 冒烟测试

```powershell
$env:ECNU_CHAT_API_KEY = "<助教自己的 ChatECNU Key>"
pwsh -NoProfile -File .\scripts\configure-pi-ecnu.ps1
Set-Location .\lab-repo
pi --list-models
pi
```

确认模型列表包含 `ecnu-plus`、`ecnu-max`，再运行：

```text
用一句话说明这个仓库的用途，不要读取 .env。
```

能收到模型回复，且调用记录中没有 `.env`，即通过。随后用 `/session` 确认
可以查看会话 ID、Token 与费用字段。

## 4. DSH 冒烟测试

```powershell
Set-Location .\lab-repo
$env:ECNU_CHAT_API_KEY = "<助教自己的 ChatECNU Key>"
pwsh -NoProfile -File ..\scripts\configure-dsh-ecnu.ps1 -Profile web
dsh web
```

打开 `http://127.0.0.1:3080`，确认 Provider 为 `ecnu-chat` 并新建会话。
发送“只回复 READY”。收到回复后，依次验证：

- 无插件时，直接读取项目中的假 `.env`；
- 运行安装命令：

```powershell
Set-Location ..              # 回到实验包根目录
dsh plugin --profile web add .\plugins\env-guard
dsh --profile web --dump-config | Select-String "dsh-env-guard"
```

- 重启 `dsh web` 后再次要求读取 `.env`，必须看到
  `[env-guard] 已拦截`；
- 在会话日志或 Trajectory 面板中确认拒绝结果被记录。

## 5. 同机版本处理

Pi 可用 Node.js 22.19+，DSH 当前要求 Node.js 24.9+。如果学校电脑另装了
Node.js 20，两个工具都可能失败。不要混用全局 `npm` 路径来“碰运气”，按
[学生环境自查](学生环境自查.md)中的 Node 版本管理步骤统一到 Node 24 LTS。

## 6. 发布到 GitHub

当前目录最初不是 Git 仓库。助教确认内容后，在**实验包根目录**执行：

```powershell
git init -b main
git add .
git commit -m "Add Pi and DSH week 2 lab"
git remote add origin https://github.com/<Owner>/<Repo>.git
git push -u origin main
```

只有目标仓库名和 GitHub 登录都明确后才能执行最后两行。发布前还要：

```powershell
git status --short
git grep -n -I -E "sk-[A-Za-z0-9_-]{12,}|API_KEY=.*[^<]"
git log -p --all -- . ':!*.lock' | Select-String "sk-"
```

第二条命令应当只匹配示例占位符；任何真实 Key 命中都必须先移除并重写历史。
公开仓库不能安全地“删除后再提交一次”来清理曾经推送过的 Key，因为旧提交仍可
恢复。

## 7. 课堂时间建议

| 时间 | 内容 |
|---|---|
| 0-5 分钟 | 收齐环境自查截图，助教只处理共性故障 |
| 5-20 分钟 | Pi 环境与精确提示任务 |
| 20-35 分钟 | 模糊提示、`/tree` 分叉与记录 |
| 35-50 分钟 | 小组归纳 Pi 的上下文策略 |
| 50-70 分钟 | DSH 无插件风险演示与插件安装 |
| 70-85 分钟 | 拦截复测、日志回放、对比表 |
| 85-90 分钟 | 六问中的至少两问口头检查与提交说明 |
