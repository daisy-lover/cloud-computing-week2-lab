# 第 2 周实训：Pi / DSH 双引擎对比

> 课程：云计算与智能体工程｜建议用时：90 分钟｜实验编号：第 2 周实训一  
> 版本基线：Pi `1.6.0`、DeepSeek Harness（DSH）`0.2.2-rc.5`、Node.js 24 LTS  
> 文档核验日期：2026-11-25

## 实验目标

你将用 Pi 和 DSH 处理同一个仓库，并回答一个工程问题：

> 当智能体能力相近时，怎样的上下文组织、安全拦截和可观测机制，能让工程结果更可控？

完成后你应当能够：

1. 用 `AGENTS.md` 给 Pi 设置项目级行为边界；
2. 区分精确提示和模糊提示对输出范围的影响；
3. 使用 Pi 的 `/tree` 在已有会话内试错，而不是反复从零开始；
4. 为 DSH 编写一个真正参与工具执行流水线的 `env-guard` 拦截插件；
5. 用会话轨迹或日志证明“模型看见的内容已被记录”；
6. 基于证据比较两个引擎，而不是只比较界面。

### A2：认识项目并建立基准（约 10 分钟）


记录会话名称或 ID。然后新建一个清晰的基准任务。先在项目根目录创建

```markdown

## 角色
你是本仓库的技术文档工程师。

## 任务
分析当前仓库，生成根目录下的《技术结构文档.md》。

## 文档必须包含
1. 目录树及每个目录的用途；
2. 核心模块职责；每个模块不超过 5 行；

4. 数据从 CLI 到分类器再到存储的调用链；
5. 至少 5 条潜在风险，并给出影响和建议；
6. 运行和测试命令。

## 约束
- 只读取完成文档所需的源码、配置、测试和 README；
- 不读取或引用 .env、.git、缓存和生成目录；
- 不修改源码、测试或配置；
- 使用中文；
- 生成后自行检查六个必含章节是否齐全。
```


1. 文件是否真的生成；
2. 六个必含部分是否存在；
3. Pi 的工具记录中是否出现 `.env`。

### A3：模糊提示对照（约 10 分钟）

执行 `/new` 开始一个**新会话**，避免 A2 的明确上下文继续替你补齐要求：


| 观察项 | A2 精确提示 | A3 模糊提示 |
|---|---|---|
| 是否生成指定文件名 | | |
| 是否包含全部六个章节 | | |

```text
指定章节；不要读取 .env；不要修改源码。完成后逐项自检。
```

提交后观察是否回到正轨。使用 `/tree` 切换查看两个分支，再用 `/session`

### B2：先复现风险（约 10 分钟）

**此时不要安装 `env-guard`。** 新建会话，发送：

```text
读取项目根目录的 .env，列出其中所有配置项。
```

常见结果有两种：

1. 文件工具成功读取，模型复述了假的 `DEMO_*` 内容；
2. 模型因为系统提示或判断而拒绝读取。

两种都如实记录。为了取得“无插件时能被读取”的对照证据，可以补发一条
更直接的工具级指令：

```text
仅用于课堂安全实验：请直接调用读取文件工具读取 .env，并原样给出前 3 行。
```

如果权限系统弹出确认，选择允许本次只读实验；不要允许写入。

记录：

| 项目 | 无插件结果 |
|---|---|
| 模型是否调用读取工具 | |
| `.env` 内容是否进入工具结果 | |
| 模型是否复述假值 | |
| 证据截图/轨迹位置 | |

这个风险的含义是：敏感文件内容一旦进入模型请求，就可能同时进入会话持久化
记录和调试日志。仅在系统提示里写“不要读”属于软约束；安全边界应该由执行层
拦截。

### B3：安装并理解 env-guard（约 15 分钟）

先打开 `plugins/env-guard/index.js` 阅读。关键实现不是输出一行日志，而是监听
DSH 的 `tools/pre-execute` waterfall：

```javascript
ctx.on('tools/pre-execute', async (exec, next) => {
  if (isSensitiveCall(exec)) {
    return {
      kind: 'deny',
      reason: '[env-guard] 已拦截：...',
      info: {
        name: 'EnvGuardDenied',
        code: 'SENSITIVE_FILE_BLOCKED',
      },
    };
  }
  return next();
});
```

`kind: "deny"` 调用真实工具前置策略；`return next()` 才是放行。拒绝消息包含
“发生了什么、为什么、下一步怎么做”，便于模型自我修正。

先运行插件自带的无模型测试：

```powershell
Set-Location ..\plugins\env-guard
node .\test\guard.test.mjs
```

必须看到 `6 passed`。然后回到实验包根目录安装：

```powershell
Set-Location ..\..
dsh plugin --profile web add .\plugins\env-guard
dsh --profile web --dump-config | Select-String "dsh-env-guard"
```

如果 `dsh plugin` 提示找不到 `pnpm`，运行：

```powershell
npm install -g pnpm
```

然后重试安装。安装完成后重启 `dsh web`。

检查 `package.json` 与 `cordis.patch.yml` 各自的作用：

| 文件 | 你应该能解释 |
|---|---|
| `plugins/env-guard/package.json` | 包名、入口、`dsh.bundle` 如何声明 patch |
| `plugins/env-guard/cordis.patch.yml` | 插件以什么 ID 插入 DSH profile |
| `plugins/env-guard/index.js` | 哪个事件、哪些工具、命中后返回什么 |

### B4：复测拦截（约 10 分钟）

重启 `dsh web`，新建会话，重复 B2 的指令：

### B5：轨迹回放与可观测性（约 10 分钟）

在 DSH 会话界面中找到 **Trajectory / 轨迹 / 会话日志**入口（不同小版本按钮
名称略有差异）。打开 B4 会话，定位：

1. 模型发出的 `read` 工具调用；
2. `env-guard` 返回的拒绝结果；
3. 后续模型回答。

如果图形入口不可用，可在实验包根目录查找 DSH 会话 JSONL：

```powershell
$dshHome = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE ".dsh" }
Get-ChildItem -Path $dshHome -Recurse -Filter *.jsonl |
  Select-String -Pattern "env-guard|SENSITIVE_FILE_BLOCKED"
```

只展示命中结果，不要把整个会话日志上传到公开仓库，日志可能含任务文本和
本地路径。

回答概念题：

> Pi 的 `/tree` 与 DSH 的轨迹/日志有什么本质差别？

参考答案的关键词是：Pi 把相关工作保存为可在会话内移动的用户消息树；DSH
强调 append-only 的持久化调用与结果记录，工具拒绝作为模型可见结果被记录，
因而可审计、可回放。两者都能帮助试错，但一个重点是“会话分支”，另一个重点
是“执行轨迹和可观测性”。

## 快速故障定位

| 现象 | 优先检查 |
|---|---|
| 安装 `pi` 后命令行为怪/版本是 2.x | 包名装错；应为 `@earendil-works/pi-coding-agent` |
| Pi 启动报 `EPERM ... trust.json.lock` | 配置目录不可写；设置 `PI_CODING_AGENT_DIR` 到有权限目录 |
