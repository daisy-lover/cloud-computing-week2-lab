# 评分与验收说明

## 合格线

学生必须提交：

1. `双引擎对比实验报告.md` 或 PDF；
2. `AGENTS.md`；
3. 可安装、可复跑的 `env-guard` 插件；
4. A、B 两张实验记录表；
5. 至少一张 Pi 分支证据图和一张 DSH 拦截/轨迹证据图。

没有真实运行痕迹、伪造 Token/耗时、泄露 Key、或 `env-guard` 只打印日志却没
真正返回拒绝决策的，不计合格。

## 建议 Rubric

| 维度 | 分值 | 观察点 |
|---|---:|---|
| 环境与可复现性 | 15 | 版本、安装、命令、记录完整；他人可复跑 |
| Pi 实验 | 25 | `AGENTS.md` 约束明确；精确/模糊对照真实；`/tree` 操作正确 |
| DSH 实验 | 25 | 正确使用 `tools/pre-execute`；拒绝可指导；复测有效 |
| 对比与机制 | 20 | 能解释上下文、分叉、插件、日志，不只罗列界面差异 |
| 安全与表达 | 15 | Key 不泄露；证据清楚；结论有边界和证据 |

## 数据真实性

- Token 和耗时以工具/网关实际显示为准。平台不回传时写“不可得”，不要估算
  后伪装成精确值。
- 模糊提示本来就可能成功，也可能不读取 `.env`。如实记录“未触发”同样有效，
  并用一次更直接的对照调用说明风险。
- 截图中必须遮住 API Key、账号标识和路径中的个人姓名。

## 防作弊检查

助教可以现场要求：

```powershell
Set-Location .\lab-repo
python -m unittest discover -s tests -v
node ..\plugins\env-guard\test\guard.test.mjs
```

再让任一学生的 `env-guard/index.js` 屏蔽测试文件 `credential.demo.pem`，确认
插件不是只对某一条界面文案做硬编码。

## 延迟提交

环境类问题若由助教在课前确认的官方兼容问题导致，应按课程规定延长截止时间；
学生自己的 Key 填错、端点漏填、Node 版本不足不属于平台故障。
