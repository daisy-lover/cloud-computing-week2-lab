# 学生环境自查

本文件用于开课前一次完成环境准备。命令默认在 Windows 11 PowerShell 中执行；
macOS/Linux 的差异会单独标注。

## 0. 一键检查

在实验包根目录执行：

```powershell
pwsh -NoProfile -File .\scripts\check-student-env.ps1
```

结果分三档：

- `[PASS]`：已满足要求；
- `[WARN]`：不影响当前代码或可稍后补，但提交前要处理；
- `[FAIL]`：必须修好才能继续实验。

脚本可重复运行，不会安装软件，也不会显示 API Key。

## 1. Node.js

### 为什么需要 Node 24

Pi `1.6.0` 要求 Node.js `>=22.19.0`，DSH `0.2.2-rc.5` 要求
`>=24.9.0`。为了在同一台电脑上完成两个实验，统一使用 Node.js 24 LTS 最
省事。

### 检查

```powershell
node --version
npm --version
```

通过标准：

- `node` 为 `v24.9.0` 或更高；
- `npm` 为 `10.x` 或更高。

### Windows 补齐

任选一种方式。

**图形安装（推荐）**

1. 打开 Node.js 官方下载页：`https://nodejs.org/`；
2. 下载带 **LTS** 标记的 Windows Installer（`.msi`）；
3. 安装时选择添加到 PATH；
4. 关闭所有终端，重新打开 PowerShell；
5. 再执行 `node --version`。

**winget**

```powershell
winget install --id OpenJS.NodeJS.LTS -e
```

安装后关闭并重开终端。如果仍显示旧版本：

```powershell
Get-Command node -All
where.exe node
```

让 `Get-Command node` 的第一条指向新安装路径，或删除旧版本相关 PATH 项。

### macOS/Linux 补齐

推荐使用 `nvm` 或系统版本管理器安装 Node 24 LTS，再执行：

```bash
nvm install 24
nvm use 24
node --version
```

### 常见错误

| 症状 | 原因 | 修复 |
|---|---|---|
| 只装了 Node 20/22 | DSH 当前引擎要求不满足 | 安装 Node 24，重开终端 |
| 命令能运行但版本仍是旧值 | 多个 Node 在 PATH 中，Shell 未刷新 | 检查 `where.exe node`，重开终端 |
| npm 全局安装 `EPERM` | 安装目录或缓存目录不可写 | 修复 Node 安装/权限，不把实验包放进只读目录 |
| 公司镜像没有新包 | 镜像同步滞后/被拦截 | 临时切官方源，或按学校网络说明使用代理 |

## 2. Python

### 检查

```powershell
python --version
```

要求 Python 3.10 或更高。本项目只使用标准库，不要求安装第三方库。

### Windows 补齐

```powershell
winget install --id Python.Python.3.13 -e
```

安装时勾选“Add Python to PATH”，然后重开终端。也可从
`https://www.python.org/downloads/` 安装。

如果 `python` 命令不存在但 `py` 存在：

```powershell
py --version
```

学习材料使用 `python` 命令；可以在 Windows 设置中关闭“应用执行别名”，或
重新安装并勾选 PATH。也可临时用 `py` 替代所有 `python` 命令。

## 3. Git

### 检查

```powershell
git --version
```

### 补齐

```powershell
winget install --id Git.Git -e
```

之后重开终端。首次使用如需提交，设置自己的身份：

```powershell
git config --global user.name "<你的名字>"
git config --global user.email "<你的学校邮箱>"
```

不要把 Key 写进 Git 配置或仓库。

## 4. PowerShell 7（Windows）

### 检查

```powershell
pwsh -NoProfile -Command '$PSVersionTable.PSVersion'
```

建议 7.2 或更高。缺失时：

```powershell
winget install --id Microsoft.PowerShell -e
```

Windows 自带的 `powershell.exe` 5.1 能运行部分命令，但本实验文档统一使用
`pwsh`，以减少编码和管道差异。

## 5. Pi

### 正确包名

`npm install -g pi` 安装的是另一个“计算圆周率”的小工具，不是本实验的
编码智能体。正确包名是：

```text
@earendil-works/pi-coding-agent
```

### 安装

```powershell
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.6.0
```

### 验证

```powershell
pi --version
pi --help
```

通过标准：

- 版本为 `1.6.0`；
- 帮助中包含 `--print`、`--mode`、`--session`。

### 配置目录不可写时

现象包括启动时报：

```text
EPERM ... .pi\agent\trust.json.lock
```

先为当前 PowerShell 选择可写目录：

```powershell
$piConfig = Join-Path $env:USERPROFILE ".pi\agent"
New-Item -ItemType Directory -Force -Path $piConfig | Out-Null
$env:PI_CODING_AGENT_DIR = $piConfig
pi --help
```

若 `%USERPROFILE%` 所在盘不可写，可临时指向非系统数据盘上的目录。这个变量
只对当前终端有效；要永久生效，可写入你的 PowerShell Profile。不要把该目录
放进公开 Git 仓库，因为其中可能包含 `auth.json`。

### 配置模型

启动：

```powershell
pi
```

在 Pi 内执行 `/login`，选择课程 Provider 并输入 Key，然后执行 `/model`
选择模型。

若课程明确要求使用环境变量且 Provider 是 DeepSeek：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host -AsSecureString |
  ForEach-Object { [System.Net.NetworkCredential]::new("", $_).Password }
Set-Location .\lab-repo
pi
```

不要在演示截图时实际显示 Key；更不要把上面的命令改成明文常量提交。

### 自定义 OpenAI 兼容网关

如果课程提供的是中转/校园网关，Pi 需要在
`$env:PI_CODING_AGENT_DIR\models.json` 中声明。模板如下；四项 `<...>` 必须由
课程方给出，不能猜：

```json
{
  "$schema": "https://pi.dev/schemas/models.schema.json",
  "providers": {
    "course-gateway": {
      "baseUrl": "<Base URL，含 /v1>",
      "api": "openai-completions",
      "apiKey": "$COURSE_API_KEY",
      "models": [
        { "id": "<模型 ID>" }
      ]
    }
  }
}
```

设置变量后验证：

```powershell
$env:COURSE_API_KEY = Read-Host -AsSecureString |
  ForEach-Object { [System.Net.NetworkCredential]::new("", $_).Password }
pi --list-models course-gateway
```

### Pi 常见错误

| 症状 | 检查 |
|---|---|
| `pi --version` 是 `2.x` | 卸载错包 `npm uninstall -g pi`，安装正确包 |
| `No models available` | 没登录、Provider 无凭据、Key 环境变量未在当前终端 |
| 端点 401 | Key 错误/过期，或把 A 平台 Key 用到了 B 平台 |
| 端点 404 | Base URL 错、缺少 `/v1`，或模型 ID 错 |
| 端点 429 | 限流/额度问题，按平台提示处理 |
| `/branch` 不存在 | 使用当前版本的 `/tree` |

## 6. DSH

### 安装

先确保 `node --version` 为 24.9+，再运行：

```powershell
npm install -g @deepseek-ai/dsh@0.2.2-rc.5
npm install -g pnpm
```

`pnpm` 只在安装 DSH 插件时需要，本实验会用到。

### 验证

```powershell
dsh --version
dsh --help
```

通过标准：

- 版本为 `0.2.2-rc.5`；
- 帮助中看到 `dsh web`、`dsh headless`、`dsh plugin` 和 `--profile`。

### 启动

```powershell
Set-Location .\lab-repo
dsh web
```

默认地址为 `http://127.0.0.1:3080`。在“设置 → 模型”配置课程模型。
首次使用会先出现“登录 / 添加 API Key”弹窗；完成模型接入后再选择本地工作区。

DSH 默认数据目录是 `$env:USERPROFILE\.dsh`。需要隔离实验数据时，先设置：

```powershell
$env:DSH_HOME = Join-Path $env:USERPROFILE ".dsh-lab"
New-Item -ItemType Directory -Force -Path $env:DSH_HOME | Out-Null
```

该目录包含会话与凭据，不能提交。

### DeepSeek 官方 API

在设置页选择 DeepSeek 并填写 Key；或在启动 DSH 前设置：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host -AsSecureString |
  ForEach-Object { [System.Net.NetworkCredential]::new("", $_).Password }
dsh web
```

### 第三方/校园网关

在“设置 → 模型 → 添加模型提供商 → 自定义模型 API”中填写：

- Provider ID：自定义且保持稳定，如 `course-gateway`；
- Base URL：由课程方提供；
- API 协议：与网关一致，多数为 `OpenAI Chat Completions`；
- API Key：课程 Key；
- 模型：手动输入模型 ID。

若“获取可用模型”失败，但课程已明确模型 ID，可以手动添加。

### DSH 常见错误

| 症状 | 原因 | 修复 |
|---|---|---|
| `Unsupported engine ... node >=24.9` | Node 版本旧 | 安装 Node 24 LTS 并重开终端 |
| 打开页面但模型不可用 | 提供商未保存/未选默认模型 | 检查“设置 → 模型”，新建会话 |
| 探测模型返回 401 | Key 错误或端点要求其他认证 | 向助教确认四项连接信息 |
| 探测返回空 | 端点无 `/models` | 手动填写已知模型 ID，不影响聊天 |
| `dsh plugin` 找不到 pnpm | 没装插件包管理器 | `npm install -g pnpm` |
| 插件安装后旧会话仍无效果 | 进程或会话没有重新加载 | 重启 `dsh web`，新建会话 |
| Windows 原生 PowerShell 管道异常 | 第三方旧版本问题 | 使用当前基线并优先 Web UI |

## 7. 模型服务连接四项

只拿到一个 API Key 不足以配置 OpenAI 兼容网关。向助教确认：

1. Key；
2. Base URL（是否包含 `/v1`）；
3. 协议（OpenAI Chat Completions / Responses / Anthropic / Gemini）；
4. 模型 ID。

四项齐全后按下面顺序排错：

1. 用最轻请求验证 Key；
2. 验证 `/models` 是否可用；
3. 用一个短聊天请求验证模型 ID；
4. 再进入 Pi/DSH。

不要把 Key 发给同学或贴到群聊。课堂统一故障应由助教在讲台用脱敏方式测试。
